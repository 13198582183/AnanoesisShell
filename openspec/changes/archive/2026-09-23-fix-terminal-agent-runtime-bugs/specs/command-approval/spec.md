## MODIFIED Requirements

### Requirement: 命令执行的输出约束
系统 SHALL 对经审批执行的命令施加执行超时与输出采集上限；执行超时 MUST 按「无输出空闲时长」语义判定——命令持续产生输出即视为正常推进，不得仅因总耗时超过单次超时设置而中断；另设独立的总时长绝对上限（默认 30 分钟）防跑飞，触顶时无条件中断并明确告知。输出过大时继续排空远端输出但只保留有界内容。无法确认命令终止或结果时 MUST 标注结果未知，不把中断请求当作终止证明。等待命令结果的外层（审批执行器、只读工具）超时 MUST 晚于命令调度内层超时——内层先以明确语义结束，外层不得先断而误判调度器无结果、回落其他通道重跑同一命令。

#### Scenario: 长时输出中的命令不被误杀
- **WHEN** 被批准的命令（如安装软件包）总执行时长超过 `run_command.timeout.seconds` 但持续产生输出
- **THEN** 系统不发送中断、不标记超时，命令正常跑完并采集、回喂结果

#### Scenario: 命令执行超时
- **WHEN** 被批准的命令在设定时限内持续无任何输出（卡住没反应）
- **THEN** 系统向所属 PTY 发送中断并提示"执行超时"，取得结束证据才标记结束，否则标记结果未知并阻止自动执行下一命令

#### Scenario: 绝对上限防跑飞
- **WHEN** 命令总执行时长触及绝对上限仍未结束（即便仍在输出）
- **THEN** 系统中断该命令并明确告知触顶，终止确认语义与空闲超时一致（取得结束证据才标记终止）

#### Scenario: 输出过大被截断
- **WHEN** 命令输出超过设定上限
- **THEN** 系统截断采集内容并标注"输出已截断"，不因停止读取堵塞远端，也不让结果无限进入模型上下文
