## Purpose

定义 AnanoesisShell 作为单机 Windows 桌面客户端的交付与运行行为：桌面入口如何拉起并收编本机后端服务、本机端口的绑定与调用授权、安装/卸载与用户数据位置、崩溃恢复，以及面向用户的发布分发与操作系统兼容验收边界。

## ADDED Requirements

### Requirement: 桌面入口拉起并收编本机后端
客户端 SHALL 以后台自动方式管理本机后端服务：启动时选择一个空闲端口、仅绑定回环地址拉起后端，待后端健康就绪后才展示主界面；退出时 MUST 请求后端优雅收尾（在途请求与审批不凭空蒸发），等待其进程结束，超时才升级为强制终止。任何路径下客户端退出后 MUST NOT 遗留孤儿后端进程。

#### Scenario: 冷启动成功
- **WHEN** 用户在无后端运行的机器上双击客户端图标
- **THEN** 客户端拉起本机后端、轮询健康端点直至就绪，随后打开显示工作区的主窗口；全程用户无需手工启动任何服务或填写地址端口

#### Scenario: 后端启动失败可感知
- **WHEN** 后端进程在就绪前退出（如端口抢占失败、数据库不可写）
- **THEN** 客户端展示明确的启动失败提示（含可读原因摘要），提供"重试"和"退出"，不静默白屏、不无限转圈

#### Scenario: 正常退出不留孤儿
- **WHEN** 用户从窗口菜单退出应用
- **THEN** 客户端先请求后端优雅关闭并等待其进程终止（超过上限时间则强制终止并记录），完成后应用全部进程消失，任务管理器中不再有残留的后端运行时进程

### Requirement: 单实例运行
同一安装的用户重复启动客户端时 SHALL 只保留一个运行实例：第二实例 MUST 退出并把已有窗口唤起置前，不得出现两个窗口争夺同一数据或各自拉起两个后端。

#### Scenario: 重复启动
- **WHEN** 应用已在运行，用户再次双击图标
- **THEN** 已有窗口被聚焦，第二个实例静默退出，不产生第二个后端进程

### Requirement: 后端进程崩溃检测与有界恢复
后端进程意外终止时，客户端 SHALL 自动重启后端并恢复界面可用；连续快速崩溃 MUST 有退避与重试上限，达到上限后转为向用户明示故障并提供重试/退出，而不是无限循环拉起。后端重启导致进行中的连接与 Agent 回合中断时，界面按既有的断线/重连语义呈现，MUST NOT 自动重发任何副作用命令。

#### Scenario: 崩溃后自愈
- **WHEN** 后端因缺陷意外崩溃
- **THEN** 客户端在数秒内自动重启后端，界面恢复可操作（已建立的 SSH 连接按断线处理，由用户决定是否重连），用户数据与凭据不因此损坏

#### Scenario: 反复崩溃止损
- **WHEN** 后端在短时间内连续崩溃达到重试上限
- **THEN** 客户端停止自动重启，展示故障说明与日志位置，提供"再试一次"与"退出"

### Requirement: 本机端口仅回环绑定且调用须持票
桌面形态的后端监听地址 MUST 限定回环，局域网内其他机器 MUST NOT 可达。回环端口上的 REST 与全部 WebSocket 端点 MUST 校验由客户端发放的本机会话凭据：桌面客户端的页面经启动令牌引导获得该凭据；未持有效凭据的请求（包括本机其他进程直连、用户用普通浏览器随意打开页面地址）MUST 被拒绝且不泄露业务能力信息。该凭据 MUST NOT 以长期口令形式落盘，客户端异常重启后 MUST 能重新引导获得。

#### Scenario: 无票访问被拒
- **WHEN** 本机某个非客户端进程或未经引导的浏览器页面向该端口的 REST/WS 端点发起请求
- **THEN** 请求被以未授权拒绝，无法列举主机、发起对话、驱动终端或响应审批

#### Scenario: 客户端页面正常通行
- **WHEN** 用户通过桌面客户端打开工作区并操作既有功能
- **THEN** 页面请求自动携带有效凭据，全部既有功能行为与 Web 形态一致，用户无额外登录步骤

#### Scenario: 局域网不可达
- **WHEN** 与用户机器同网段的另一台机器尝试连接该端口
- **THEN** 连接失败（拒绝或超时），本机端口不对局域网提供服务

### Requirement: 主界面加载与内容边界
客户端窗口 SHALL 加载由本机后端同源托管的应用界面；窗口内 MUST NOT 导航到任意远端网页，也不得向页面内容暴露本机文件写入或任意程序执行的通道；界面中出现的模型回复与远端输出继续按不可信文本渲染。

#### Scenario: 同源加载
- **WHEN** 主窗口完成加载
- **THEN** 页面与其调用的 REST/WS 同源，无跨源放行配置需求；页面内链接型内容不触发窗口自身跳转到外部站点

### Requirement: 启动画面与开发者署名
客户端 SHALL 自启动瞬间展示启动画面（splash）：画面 MUST 呈现应用名 AnanoesisShell、宗旨文案「让 Linux 运维不再困难」与开发者署名「李仔文 / liziwen」；主界面就绪后启动画面 MUST 自动退场切入工作区；启动失败时启动画面 MUST NOT 静默消失，MUST 转入用户可感知的错误态。安装包与程序元数据（exe 文件属性、Windows「应用和功能」）中的发行者/公司名 MUST 显示为 liziwen（李仔文）。本版本不含 Authenticode 代码签名（依赖购买证书），发布说明 MUST 如实标注未经签名（下载者会见到系统来源警告），MUST NOT 伪称已签名。

#### Scenario: 冷启动出现启动画面
- **WHEN** 用户双击图标且后端尚在启动
- **THEN** 立即展示含应用名、宗旨文案与开发者署名的启动画面，后端就绪后画面自动退场、主窗口出现

#### Scenario: 启动失败画面兜底
- **WHEN** 后端启动失败或反复崩溃达到止损
- **THEN** 启动画面不消失而是切换为失败提示（可读原因摘要＋重试/退出），不出现"点一下闪一下就没"的白屏体验

#### Scenario: 安装后发行者可见
- **WHEN** 用户在 Windows「应用和功能」查看本应用，或查看安装包/exe 的"属性-详细信息"
- **THEN** 发行者/公司显示 liziwen（李仔文）

### Requirement: 安装、卸载与数据位置
客户端 SHALL 以 Windows `.exe` 安装包分发：默认安装到 C 盘程序目录，用户 MUST 可在安装时自选安装路径；安装需要管理员提权属预期行为。程序目录内 MUST NOT 写入用户数据或日志；数据库、凭据保护与用户配置的位置与 Web 形态保持同一用户目录约定，同一台机器上从 Web 形态转用桌面客户端时既有数据 MUST 直接可用。卸载 MUST NOT 默认删除用户数据；如需删除 MUST 有用户明确选择。

#### Scenario: 自选路径安装后首启
- **WHEN** 用户运行安装包、选择非默认路径完成安装并首次启动
- **THEN** 应用正常拉起并可连接远端主机，此前在同一用户目录下使用 Web 形态积累的主机、对话与凭据全部原样可见

#### Scenario: 卸载保留数据
- **WHEN** 用户执行卸载且未明确勾选清除数据
- **THEN** 程序文件被移除，用户目录下的数据库与配置仍在，重装后恢复原状态

### Requirement: 首个 Release 发布与可下载
本变更交付时 MUST 在主仓库 GitHub 上创建首个 Release（版本标识 v0.1.0），挂载与 Windows 10/11 对应的 `.exe` 安装包供用户直接下载；Release 说明 MUST 如实标注未经代码签名（首次下载会有系统来源警告）与自动更新未实现这两项已知限制。

#### Scenario: 用户从 Release 页获取安装包
- **WHEN** 用户打开主仓库的 GitHub Releases 页面
- **THEN** 存在 v0.1.0 Release，其中可直接下载本客户端安装包，说明页载明的安装要求与实际行为一致

### Requirement: Windows 10/11 兼容验收边界
客户端承诺支持的客户端操作系统为 Windows 10 与 Windows 11（Windows 7 支持经决策放弃，不再承诺）。发布前 MUST 在干净的 Windows 10 与 Windows 11 环境各完成至少一轮：无预装 Java/Node 条件下的安装、首启、SSH 连接与终端交互、AI 对话含审批执行、退出无孤儿进程、中文与空格路径；未在干净虚拟机完成验证的项目 MUST 标为未验证，不得对外宣称通过。

#### Scenario: 干净 Win11 首装首用
- **WHEN** 在未安装 Java/Node 的干净 Windows 11 虚拟机上安装并启动客户端
- **THEN** 全流程无需用户安装任何额外运行时，核心功能可用，退出后无残留进程

#### Scenario: 未验证项不外宣
- **WHEN** 某发布物仅在开发机或仅 Windows 11 完成验证
- **THEN** 发布说明与文档不宣称覆盖 Windows 10（或其他未验证版本/架构）
