# 后端、SSH 与 AI 执行规范

> 适用于 `backend/`。依据当前 `pom.xml`、controller/service/ssh/ai/approval/ws/security 分层及测试提取；标为“待完善”的内容不得视作已实现保证。

## 1. 分层与代码约定
- 使用 Java 17 可编译的语法/API，不因开发机使用 JDK 21 就引入 Java 21 专属特性；依赖版本优先由 Spring Boot parent / Spring AI BOM 管理。
- controller 实现 OpenAPI 生成接口，做入参/响应适配；service 承担业务事务和规则；mapper/entity 限于持久化；ws 负责协议校验、连接归属与消息分发；SSH、AI、审批、凭据各守边界。
- 延续构造器注入，服务依赖显式声明；公共方法以中文 Javadoc 解释业务目的、参数、返回、异常及资源所有权，不复制冗长过程性注释。
- 统一经异常处理器把业务异常转换为契约错误；用户提示区分认证失败、不可达、模型调用错误、凭据保护不可用，不返回内部堆栈或原始敏感报文。
- 业务 ID、时间转换复用 support 中的统一入口；数据库枚举与契约枚举不一致时显式映射并测试，不依赖 `Enum.valueOf` 碰巧同名。
- OpenAPI 生成输出位于 `target/generated-sources/openapi`，保持 `interfaceOnly` / `skipDefaultInterface`，不通过生成接口默认 501 掩盖缺失实现。

## 2. SSH 与资源生命周期
- 仅面向 Linux 远端。人工交互走 PTY，AI 执行走独立 exec；二者的输入、输出、会话归属不得混用。
- SSHClient、channel、流、线程任务由创建/持有方明确关闭；认证失败、超时、主动退出、远端关闭及 WS 断开均纳入清理测试。资源清理应幂等且保留最初错误。
- 建连前设置连接/握手超时与 keepalive；exec 执行必须有超时、输出字节上限和可见的截断/失败状态；不把缺失退出码伪造为成功。
- 非交互 exec 不用于交互式密码输入或编辑器。路径参数通过既有 shell 转义入口处理；只读工具不得接受可任意拼接执行的命令片段。
- 每条终端 WS 必须核对 session_id 归属，不能让其他浏览器连接控制不属于它的 SSH 会话；保持并发配额与空闲回收。
- 主机身份校验目前为接受任意指纹的已知安全缺口，禁止把这一行为推广为正式安全规范；生产发布前须完成首次指纹确认、持久化及变更拒绝的设计与验证。

## 3. AI 工具与审批
- 模型从当前设置动态构造，不硬编码 API Key，不退回内置端点或默认凭据；provider 差异留在适配层。
- 保持 `internalToolExecutionEnabled=false`，应用负责工具路由；只读工具自动执行，任意 `run_command` 均先经审批，禁止以“看起来安全”为由绕过闸门。
- 审批的 pending、批准/拒绝/超时与执行成功/失败分别建模；用户响应与定时器竞态只能有一个有效结果，重复/过期决定不得重复执行。
- 不在数据库写事务中等待模型、SSH 或用户审批；审批挂起资源必须在结束/超时后释放。
- 工具参数/结果、模型回答与思考字段保持结构化；对话重建延续持久化上下文，不把工具结果当用户授权。
- 模型中断、工具失败、WS 断开采用明确的状态与清理策略；重连不能自动重发副作用命令。当前 AI 断开后仍继续回合、审批不补发，需要后续恢复机制单独设计。
- 取消/停止类能力（如 `AiAgentService.stop`）必须接上真实触发入口（契约上行帧 + handler 分支），否则即为死代码；停止类命令按幂等通知设计，未命中目标静默成功。
- 凡按异常类型分支的中断语义，必须同时识别被框架包装的 InterruptedException（cause 链遍历，如 langchain4j 的 ReactiveException）；捕获后跑阻塞收尾（WS 发送、JDBC）前必须显式决策 `Thread.interrupted()` 清标志还是恢复标志并把理由写进注释——标志残留会让同线程第一帧 blocking send 即失败。

## 4. 凭据与审计
- 凭据统一通过 CredentialStoreService 和加密服务处理，OS 密钥库托管主密钥、AES-256-GCM 信封存密文；不得把主密钥放在数据库、明文文件或前端存储。
- 保护不可用时失败关闭，不降级明文；主密码派生回退目前仅有底层能力，没有完整设置/解锁业务流程，不得宣称用户已可使用。
- 凭据按需解密；可擦除数组在 finally 中清理，避免额外复制为不可擦除 String。响应只返回配置状态，不返回密码/私钥/API Key。
- 不记录完整 DTO、认证对象、HTTP 请求体或模型原始报文；保留现有 HTTP 日志防护与日志泄密回归测试。`writeOnly`、字符串截短和日志级别均不能替代脱敏。
- 审计和聊天中可能出现用户输入/命令输出携带的秘密；后续敏感内容处理必须覆盖持久化、日志、错误、导出等出口，不能只保护 credentials 表。当前审计文本仍原样存储，此项尚未闭环。
- 任何备份/回滚能力必须有独立设计、审批和验证；已有审批不等于已自动备份，提示词建议备份不等于备份成功。

## 5. 测试边界
- 单元与集成测试使用 JUnit / Spring Boot Test、临时 SQLite 和内嵌 SSHD；不得依赖真实 Linux 生产机、个人 API Key 或用户数据库。
- 覆盖契约错误、权限/连接归属、超时、重复审批、凭据泄密、输出截断与资源释放；安全测试通过只证明所覆盖路径，不等于整库无安全风险。
- 真实 provider 能力验证单列：原生 tools、tool_calls、流式与思考字段兼容性均须有脱敏证据，不能以其他 OpenAI 兼容服务可用替代 MindIE 实测。
