## Purpose

提供与大模型服务对接的统一接入能力，兼容 OpenAI 风格的对话补全接口，支持运行时配置模型端点与凭据，并支持思考与非思考两种输出模式，以适配内网自托管推理服务与未来的本地模型服务。

## ADDED Requirements

### Requirement: OpenAI 兼容端点接入

系统 SHALL 通过可配置的 base URL、模型名与 api key 对接任何 OpenAI 兼容的对话补全端点，MUST NOT 将端点地址或模型名写死于代码。

#### Scenario: 连接内网推理服务

- **WHEN** 用户配置了内网 OpenAI 兼容端点的 base URL、模型名与 api key
- **THEN** 系统使用该配置向端点发起对话请求并获取响应

#### Scenario: 端点不可达或返回错误

- **WHEN** 配置的端点不可达或返回错误状态
- **THEN** 系统向用户报告明确的连接或调用错误，不静默失败

### Requirement: 模型配置管理

系统 SHALL 允许用户在设置中管理一个或多个模型配置（provider 名称、base URL、模型名、api key），并可指定当前生效的配置。

#### Scenario: 新增并切换模型配置

- **WHEN** 用户新增一个模型配置并将其设为当前生效
- **THEN** 系统后续对话请求使用该配置

#### Scenario: 编辑模型配置

- **WHEN** 用户修改当前生效配置的模型名或端点并保存
- **THEN** 系统后续对话请求使用更新后的配置

### Requirement: 思考与非思考双模式

系统 SHALL 支持思考模式与非思考模式两种输出方式；在思考模式下 MUST 能获取并区分模型的"思考过程"与"最终回答"，并允许用户选择默认模式。

#### Scenario: 思考模式返回思考过程

- **WHEN** 以思考模式发起请求且模型返回思考过程
- **THEN** 系统将"思考过程"与"最终回答"分别标识，供界面区分展示

#### Scenario: 非思考模式

- **WHEN** 以非思考模式发起请求
- **THEN** 系统仅获取并使用模型的最终回答

### Requirement: 流式响应

系统 SHALL 支持以流式方式接收模型输出，并在生成过程中逐步向前端推送增量内容。

#### Scenario: 流式输出增量展示

- **WHEN** 模型以流式返回回答
- **THEN** 系统逐步向前端推送内容增量，而非等待完整响应后再一次性返回
