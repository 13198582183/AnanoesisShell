# 前端编码、样式与交互规范

> 适用于 `frontend/`。以当前活跃的 `App.vue`、`WorkspaceView.vue`（多 tab 工作区）、`TerminalTimeline.vue`（单一 xterm 时间线）及审批弹窗/通道封装为基线（add-multi-session-agent-terminal 变更后；`TerminalView.vue` 为旧单会话页）。下列约束用于后续新增/修改，不表示存量页面已全面达标。

## 1. 组件与状态
- 使用 Vue3 Composition API、`<script setup lang="ts">` 和 TypeScript；组件 PascalCase，业务变量 camelCase，类型导入使用 `import type`。
- `views/` 负责路由页面编排，`components/` 负责可复用交互，`stores/` 用 Pinia 管理共享资源状态；页面临时状态使用局部 ref/computed。不要把网络协议和 DOM 操作塞进配置 store。
- REST 统一经 `@/api` 导出的生成客户端调用；不在页面另写字段转换。REST 的 camelCase 对象与 snake_case 线格式由生成器转换；WS 保留契约中的 snake_case。
- WS 复用 `WsChannel` 及 terminal/approval/ai 通道工厂；入站数据做类型守卫，不以类型断言代替校验。
- 使用现有 `@/` 别名；生命周期中成对管理连接、订阅、DOM 监听器、定时器和 xterm 资源。
- 路由参数变化不能只靠 onMounted；异步加载必须防止旧响应覆盖新主机/会话状态。拆分组件时维护单一实现，避免新旧聊天视图各自演进。

## 2. 视觉基线
- 延续终端中心的深色工作区：左侧 48px 图标栏、主区域弹性铺满、底部 24px 状态栏；不以大面积装饰挤压终端。
- 全局重置和应用壳由 App 管理；页面/组件使用 scoped CSS，避免全局选择器污染 xterm 内部 DOM。复用区域保留 `min-width: 0`，滚动由具体面板承担。
- 延续现有色板，新组件不随意另起主题：

| 语义 | 颜色 |
| --- | --- |
| 主背景 | `#0d1117` |
| 面板背景 | `#161b22` |
| 分隔线/边框 | `#21262d` / `#30363d` |
| 主要/辅助文本 | `#c9d1d9` / `#8b949e` |
| 激活/链接 | `#58a6ff` |
| 成功/失败 | `#3fb950` / `#f85149` |
| 审批警示 | `#f0883e` |

- 当前色值仍散布于 scoped CSS，尚无统一 CSS token 文件；新增公共 token 需集中管理，不声称现有样式已令牌化。
- UI 使用系统字体回退链；命令、路径、工具参数、终端使用等宽字体。图标延续内联 SVG，不能仅靠图标或颜色传达操作含义。
- 紧凑间距沿用现有 4/8/12/16px 节奏、6–8px 圆角；动画轻量，不干扰终端输入。验证 Windows DPI 缩放后按钮、表单和审批内容仍可达，不锁死大窗口尺寸。

## 3. Shell / Agent 交互
- Shell/Agent 是工作区模式，不等于不同主机；切换时保持明确的目标主机提示，不擅自重发命令或新建会话。
- 未选主机时只提供无主机可用的能力，不能发送空 host_id 建连；WS connected 不等于 SSH ready，收到服务器分配的 session_id 后才允许发送输入。
- xterm 处理 ANSI、光标、Ctrl-C；不要用普通文本框替代终端输入协议。退出与失败路径必须清理会话状态，并给用户可理解的反馈。
- Agent 生成态 Ctrl+C 升级为打断：写 `^C` 留痕 + 上行 `stop_turn` 后发起方必须**本地闭环**（复位生成态、写停止注记），不依赖后端收尾帧送达（中断可能杀死 WS 发送链）；后端若送达则幂等兼容。
- 打断/取消类操作的状态复位，在设计时必须回答“真相源帧是否保证送达”；当取消手段本身可能破坏传输通道时，禁止把用户可感知的复位唯一押在远端帧上。
- `fit()` 只调整本地网格，不能视为远端 PTY resize 已实现。新增 resize 需同步 AsyncAPI、前后端和测试。
- 模型输出区分思考内容、最终回答、工具调用及结果/拒绝状态；流式消息按会话与消息 ID 合并，不能串台。发送中防重复提交，断线或错误不得永久停留在加载状态。
- 模型和服务器输出默认按文本渲染，禁止直接 `v-html`；未来支持 Markdown/链接时须另行增加安全过滤。

## 4. 审批与表单
- 当前审批入口为 App 中的全局 `ApprovalCard`：右下角、状态栏上方、非阻断悬浮卡片；显示目标服务器、工具/命令、分析、倒计时及明确的“执行/取消”。不恢复为全屏遮罩，不抢走正在输入的终端焦点。
- 执行决定必须关联 approval_id；前端超时只关闭展示并提示，不伪造 approval_response。最终取消与是否执行以服务端为准。
- 后续并发审批必须排队或独立呈现，不能覆盖尚未处理的请求；发送失败不能显示为审批成功，也不能自动重放副作用决定。当前单卡状态和断线反馈仍需完善。
- 表单保留加载、空态、校验失败、请求失败与保存中状态；持久化成功后再更新成功提示。删除操作需明确确认，不把网络错误当作空列表。
- 编辑密码/私钥/API Key 不回填明文，仅显示“已配置”等标志；保留、替换、清除按契约语义区分，不能用空值误覆盖凭据。
- 图标按钮有可访问名称，表单 label 关联输入，焦点可见；Shell/Agent 标签提供选中语义与键盘操作。错误不能只靠红色或短暂 toast 表达。

## 5. 验证要求
- 使用 Vitest + Vue Test Utils；测试命名描述用户行为，延续 `data-region` / `data-action` / `data-field` 稳定选择器，避免依赖装饰 CSS。
- 多通道 WS mock 每次构造独立实例，按通道验证消息；定时器测试覆盖到期与清理，避免监听器互相覆盖。
- 组件测试必须覆盖真实路由使用的组件；旧 `AiChatView` 测试通过不能替代当前 `TerminalView` 的 Agent 回归。
- 覆盖主机切换、历史加载竞争、断线、审批批准/拒绝/超时、敏感字段不回填；UI 改动补浏览器验证，记录场景和结果。
- 底栏健康状态须验证真实健康端点及响应内容；开发服务器返回 200 HTML 不代表后端健康。当前健康代理/判定逻辑仍需完善。
