# terminal-workspace Delta: reset-agent-memory-on-reconnect

## MODIFIED Requirements

### Requirement: 断线重连
终端会话结束（服务端回收、远端关闭）或连接中断后，系统 SHALL 将所属 tab 置为断线终态：在终端内展示断线原因与重连指引，清空已失效的会话标识使后续输入不再路由到死会话（避免逐帧错误风暴），并提供两个手动重连入口：终端内按 `r`/`R` 键（对标 MobaXterm）与工具栏“重连”按钮（对标 FinalShell）。系统 MUST NOT 自动重连：重建会话会丢失工作目录与运行中程序，上下文切换 MUST 由用户显式确认。重连 SHALL 复用既有连接链路重新发起会话建立，并 MUST 连带重建 AI 与审批通道（三条通道同源拉起：整条连接断开后若不一并恢复，Agent 提问与审批会在重连后静默失效），新会话标识 MUST 覆盖旧值并被后续输入、审批与 AI 路由采纳；已渲染的终端历史 MUST NOT 因重连被清空。重连发起时系统 MUST 同时重置该 tab 绑定的 Agent 对话记忆：先打断旧对话的在飞回合（沿停止链路由后端中断模型流、使未执行审批失效、终止任务执行）并解除其生成中状态，再解绑当前对话使下一次提问在全新对话上推进——新建终端会话是工作目录与环境全部归零的全新 Shell，沿用旧对话会让模型携带与实况脱节的幻觉上下文，而旧回合不被终止会继续占用会话执行槽、阻塞新会话的提问；已产生的对话记录 MUST NOT 被删除，仍可在历史中查阅。

#### Scenario: 空闲回收后重连
- **WHEN** 终端会话被服务端空闲回收下发关闭事件，用户在断线提示后按 `r` 或点击“重连”按钮
- **THEN** 系统重新建立会话并采纳新会话标识，终端继续可用且原屏幕历史保留；新会话为全新 Shell（目录重置为登录目录），断线提示行向用户明示这一边界

#### Scenario: 断线态输入拦截
- **WHEN** 会话已终结时用户在终端继续键入
- **THEN** 除重连快捷键 `r`/`R` 外其余输入被丢弃，不向已失效会话发送任何字节，终端不出现“会话不存在”错误刷屏

#### Scenario: 连接中断后手动恢复
- **WHEN** WebSocket 连接整体断开（如后端重启）后恢复重连
- **THEN** 系统展示断开提示并等待用户触发；触发后重建连接与终端会话，期间不提供自动重试，用户可选择忽略断线提示改而关闭 tab

#### Scenario: 重连重置 Agent 对话记忆
- **WHEN** 用户在该 tab 已与 Agent 对话（含回合正在执行或等待审批）后经历断线并触发重连
- **THEN** 旧对话的在飞回合被打断、未执行的任务与审批终止，该 tab 的 Agent 对话绑定被清空并向用户展示重置注记行，下一次 Agent 提问在全新对话上推进且不再被「本会话正在处理上一条提问」阻塞；旧对话记录保留在历史中可查，未产生过对话的 tab 重连时不出现重置注记
