## MODIFIED Requirements

### Requirement: 受控停止任务
系统 SHALL 支持停止当前 Agent 任务，并清算模型流、未执行工具与审批；停止确认之后到达的旧事件不得继续触发工具执行。停止不保证撤销已经发生的远端副作用。

Agent 模式下用户按 Ctrl+C MUST 打断在飞回合，体验对标 Shell 模式 Ctrl+C 打断程序：前端在当前 tab 终端写入 `^C` 留痕并经 AI 通道上行 `stop_turn` 帧（携带 conversation_id），随后 MUST 立即本地闭环（复位生成态、写停止注记行），不依赖后端收尾帧送达；后端命中在飞回合时中断工作线程并以带停止注记的 final 帧尽力收尾（收尾前 MUST 清除线程中断标志，否则 Tomcat WS 发送会被打断导致丢帧），收尾帧若送达对前端是幂等的；未命中时静默忽略（停止是幂等通知，不返回错误帧）。

停止 MUST 穿透到远端与工具回喂层，不得半途被吞：①命中在飞回合时，除中断工作线程外，系统 MUST 经该回合绑定的连接会话定位命令调度器，对其正在执行的远端命令发送中断（否则远端长任务会在本地停止后继续跑）；②系统 MUST 维护不依赖线程中断标志的权威停止状态（回合进行中的轮首、每次工具调用前、流式增量处理时均据此终止），因为工具回退/审批回退会把 InterruptedException 吞成普通失败、导致中断丢失后回合按上一步继续推进；③停止 MUST NOT 被伪装成工具失败结果（tool_result 错误态）回喂给模型——一旦回喂，模型会把"用户停止"当作"这条命令失败了，换条路重试"，正是"停不下来"的症状。

#### Scenario: 生成中停止并切回人工
- **WHEN** 用户停止正在生成的任务并切回 Shell
- **THEN** 模型生成终止、未执行工具失效，终端在状态确认后归还人工输入权，保留已发生操作及结果记录

#### Scenario: Agent 生成中 Ctrl+C 即时打断
- **WHEN** Agent 回合在飞（思考/工具循环中）用户在当前 tab 终端按 Ctrl+C
- **THEN** 终端立即可见 `^C` 留痕与停止注记行（如「本轮处理已被用户停止。」），生成态本地立即复位、输入区恢复可用，即使后端收尾帧因连接中断未送达；若回合恰已自然结束，`stop_turn` 被忽略且已有输出不受影响

#### Scenario: 停止穿透打断远端在飞命令
- **WHEN** Agent 回合正阻塞在一条已批准、在远端 PTY 执行的命令上，用户停止该回合
- **THEN** 系统向该连接会话的调度器发出对在飞命令的中断，远端输出被截断；停止不以 tool_result 错误态回喂模型，回合不再推进到下一轮工具循环

#### Scenario: 工具阶段被中断不被回退层吞没
- **WHEN** 停止信号落在只读工具执行或审批回退等待期间（该路径历史上会把中断转成普通失败）
- **THEN** 系统据权威停止状态在下一个检查点终止回合并收尾停止注记，用户看到停止而非红字报错或继续执行
